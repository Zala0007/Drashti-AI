# P0.3 Local Federation Runbook

Status: current local/evaluation procedure for sanitized sources. This is not an internet-facing or production-government-feed deployment guide.

This runbook adds P0.3 federation configuration and the P0.3R supervised media runtime to the existing P0.1/P0.2 backend and UI workflow. It demonstrates encrypted connection profiles, encrypted department-scoped device credentials, bounded adapter probes, authenticated direct-stream handoff, ONVIF Media1 profile negotiation, continuous FFmpeg supervision, and same-origin HLS live view. It does not provide durable recording, AI, alerts, route reconstruction, an external production vault, or production identity/authorization.

## 1. Safety gate before starting

Use only a source that you own or are explicitly authorized to probe. A probe creates real outbound network traffic. Do not enter a government feed, credential, private topology, production vault path, or third-party endpoint into a development workstation without the required owner and security approval.

For hackathon evidence:

- use sanitized labels and an isolated representative source;
- prefer a controlled recorded file or a simulator on a dedicated local subnet;
- keep raw endpoints and credential references out of terminal history, screenshots, recordings, source files, issues, and chat;
- configure the narrowest exact CIDR needed;
- stop and investigate if an endpoint appears in an API response or log.

## 2. Prerequisites

- the P0.1 local prerequisites and Python environment from `docs/deployment/P0.1-LOCAL.md`;
- current backend dependencies installed from `apps/backend`;
- a migrated database containing at least one P0.1 camera;
- an authorized representative source for an adapter probe;
- ports `8000` and `5173` available, unless local ports are changed;
- system time synchronized.
- FFmpeg available through `FFMPEG_BINARY`, the system `PATH`, or the optional `imageio-ffmpeg` fallback. The container image installs a system FFmpeg build.

Docker/PostGIS is not required for the SQLite developer path. SQLite remains a single-developer fallback and does not validate production concurrency, HA, or PostGIS behavior.

## 3. P0.3 environment settings

| Setting | Required | Local meaning | Production requirement |
|---|---:|---|---|
| `FEDERATION_ENCRYPTION_KEY` | for protected profile operations | URL-safe Fernet key encoding 32 random bytes | retrieve versioned envelope key through managed KMS/HSM/secret service; do not manually distribute a shared long-lived key |
| `FEDERATION_ENCRYPTION_KEY_ID` | recommended | non-secret label identifying the configured key version | stable managed key/version identifier used for rotation and recovery |
| `FEDERATION_ALLOWED_CIDRS` | for private/loopback network sources | comma-separated exact probe destination ranges; empty is fail-closed for private/loopback | per-edge/site egress policy enforced both by application and firewall/container network policy |
| `FEDERATION_PROBE_TIMEOUT_SECONDS` | no | total synchronous network-probe deadline across resolved-address attempts; local default is `5` and the service clamps it to `0.25`-`30` seconds | set from measured protocol/site behavior, with queue/worker deadlines and backpressure |
| `FEDERATION_MEDIA_ROOT` | for recorded-file source | only filesystem tree a recorded adapter may reference; local default is `./media` | isolated staged object/file service with scanning, ownership, retention, and no arbitrary host filesystem access |
| `FFMPEG_BINARY` | no | explicit trusted FFmpeg executable; otherwise resolve from `PATH` or packaged fallback | pinned, signed, vulnerability-managed media-worker image |
| `FEDERATION_RUNTIME_ROOT` | no | private generated HLS root; local default `./runtime/streams` | encrypted/private ephemeral worker volume, never an unauthenticated static mount |
| `FEDERATION_SEGMENT_DURATION_SECONDS` | no | HLS segment target; default `2` | tune from measured latency, GOP, I/O, and player behavior |
| `FEDERATION_PLAYLIST_WINDOW` | no | rolling live-window segment count; default `6` | bounded per-session storage and retention policy |
| `FEDERATION_WATCHDOG_SECONDS` | no | media-progress freshness threshold; default `12` | tune by source/site and alert SLO |
| `FEDERATION_MAX_BACKOFF_SECONDS` | no | retry-delay cap; default `30` | combine with per-site retry budgets and circuit policy |
| `FEDERATION_MAX_RESTARTS` | no | terminal retry limit; default `8` | durable circuit state and operator workflow |
| `FEDERATION_STOP_TIMEOUT_SECONDS` | no | graceful child-process stop deadline; default `5` | measured worker termination budget |
| `FEDERATION_MAX_ACTIVE_SESSIONS` | no | process-local admission limit; default `8` | worker-pool capacity/admission derived from load tests |

Do not put any `FEDERATION_*` secret in a browser-visible `VITE_*` variable. `FEDERATION_ALLOWED_CIDRS` contains sensitive topology in a real environment and should be protected as operational configuration even though it is not credential material.

## 4. Generate an ephemeral local encryption key

Generate a new key into the current PowerShell process without printing it:

```powershell
$localFederationKey = .\.venv\Scripts\python.exe -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode('ascii'))"
$env:FEDERATION_ENCRYPTION_KEY = $localFederationKey.Trim()
$env:FEDERATION_ENCRYPTION_KEY_ID = "local-demo-2026-08"
Remove-Variable localFederationKey
```

The value remains in the process environment and is inherited by the backend started from that terminal. Do not print it, paste it into a command argument, commit it, or include it in a screen recording.

An ephemeral key is appropriate only with a disposable fresh local database. If the terminal/key is lost, existing encrypted profiles cannot be recovered. For a persistent local evaluation database, inject the key from an approved OS/user secret facility. A plaintext `.env` file is not production key custody even when Git ignores it.

To confirm that configuration exists without exposing it:

```powershell
if ([string]::IsNullOrWhiteSpace($env:FEDERATION_ENCRYPTION_KEY)) { throw "Federation key is not configured" }
```

Do not echo `$env:FEDERATION_ENCRYPTION_KEY`.

## 5. Configure the probe boundary

### Controlled recorded-file demonstration

Create a dedicated media directory under the repository and use only sanitized media you are authorized to process:

```powershell
New-Item -ItemType Directory -Force .\media | Out-Null
$env:FEDERATION_MEDIA_ROOT = (Resolve-Path .\media).Path
$env:FEDERATION_ALLOWED_CIDRS = ""
$env:FEDERATION_PROBE_TIMEOUT_SECONDS = "5"
```

Copying or downloading media is intentionally outside this runbook. Verify its source, rights, and privacy before placing it under the media root. Do not use arbitrary absolute paths outside this directory.

### Isolated loopback simulator

Only when an authorized simulator is intentionally bound to loopback:

```powershell
$env:FEDERATION_ALLOWED_CIDRS = "127.0.0.1/32,::1/128"
$env:FEDERATION_PROBE_TIMEOUT_SECONDS = "5"
```

This example is not a recommendation to allow loopback in shared/production workers. An SSRF-reachable worker with loopback access can target local admin services. Production network policy should deny it unless a documented isolated workload requires it.

### Authorized private test subnet

Set only the exact approved host/subnet ranges supplied by the network owner:

```powershell
$env:FEDERATION_ALLOWED_CIDRS = "<approved-test-cidr>"
```

Replace the placeholder before startup. Do not use a broad private supernet merely for convenience. Never use `0.0.0.0/0` or `::/0`.

The implemented network adapters connect directly to a policy-approved resolved IP; HTTP-family probes retain the hostname only for `Host`/TLS SNI, disable redirects, and do not inherit proxy settings. Production protection still requires operating-system/container firewall or controlled-egress enforcement so a future or compromised adapter cannot bypass application policy.

## 6. Database migration

Set one absolute SQLite URL before changing directories so Alembic and Uvicorn cannot accidentally operate on two different relative database files:

```powershell
$localFederationDb = (Join-Path (Get-Location) "drishti_registry.db").Replace('\', '/')
$env:DATABASE_URL = "sqlite:///$localFederationDb"
```

Apply the repository migrations from the backend directory:

```powershell
Push-Location apps/backend
..\..\.venv\Scripts\python.exe -m alembic upgrade head
..\..\.venv\Scripts\python.exe -m alembic current
Pop-Location
```

For a shared PostgreSQL environment set `AUTO_CREATE_SCHEMA=false`; Alembic history is the schema authority. A SQLite result does not validate PostgreSQL locking, query plans, worker concurrency, or migration rollout behavior.

## 7. Start the backend and UI

In the same terminal that holds the encryption/network configuration:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --app-dir apps/backend --no-access-log
```

`--no-access-log` is required for the local security posture. The application emits a structured request event with method/path/status/request ID/latency while omitting query, headers, and body.

In a second terminal:

```powershell
npm --prefix apps/frontend run dev
```

Open:

- UI: `http://localhost:5173`
- generated OpenAPI: `http://localhost:8000/docs`
- readiness: `http://localhost:8000/health/ready`

Do not copy a protected endpoint into Swagger/OpenAPI while recording the screen. Prefer the product UI, keep the protected input outside the capture area, submit it once, and confirm that the resulting detail view is redacted.

## 8. Compose profile: PostGIS + API + UI

The repository supplies `deployment/docker/compose.p0.3.yml`. It binds API/UI ports to loopback, keeps PostgreSQL off the host network, requires an explicit database password and federation key, applies Alembic before startup, and mounts `runtime/media` read-only inside the backend container.

Generate local-only values into the current PowerShell process without writing them to `.env` or printing them:

```powershell
$composeFederationKey = .\.venv\Scripts\python.exe -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode('ascii'))"
$env:FEDERATION_ENCRYPTION_KEY = $composeFederationKey.Trim()
$env:FEDERATION_ENCRYPTION_KEY_ID = "local-compose-2026-08"
Remove-Variable composeFederationKey

$env:POSTGRES_PASSWORD = Read-Host "Temporary local Postgres password" -MaskInput
$env:FEDERATION_ALLOWED_CIDRS = ""
$env:FEDERATION_PROBE_TIMEOUT_SECONDS = "5"
New-Item -ItemType Directory -Force .\runtime\media | Out-Null
```

Use a unique password. `-MaskInput` requires PowerShell 7; do not place a password literal in shell history. For an approved private test source, set the same narrowly scoped CIDR policy described earlier before startup.

Validate without rendering interpolated secrets, then start:

```powershell
docker compose -f deployment/docker/compose.p0.3.yml config --quiet
docker compose -f deployment/docker/compose.p0.3.yml up --build -d
docker compose -f deployment/docker/compose.p0.3.yml ps
```

Do not run or capture an unredacted `docker compose ... config` after setting secrets; normal config output can include interpolated password/key values. If the installed Compose version does not support `config --quiet`, validate in a protected terminal and do not save/share its output.

Inspect only application logs and never use commands that dump container environment variables:

```powershell
docker compose -f deployment/docker/compose.p0.3.yml logs --tail 100 backend
docker compose -f deployment/docker/compose.p0.3.yml logs --tail 100 frontend
docker compose -f deployment/docker/compose.p0.3.yml logs --tail 100 postgres
```

Stop while retaining the database volume and media files:

```powershell
docker compose -f deployment/docker/compose.p0.3.yml down
Remove-Item Env:FEDERATION_ENCRYPTION_KEY -ErrorAction SilentlyContinue
Remove-Item Env:FEDERATION_ENCRYPTION_KEY_ID -ErrorAction SilentlyContinue
Remove-Item Env:POSTGRES_PASSWORD -ErrorAction SilentlyContinue
```

Do not add `--volumes` to routine shutdown; that is destructive. Retain/recover the matching key if the encrypted profiles in the volume must remain usable.

This Compose profile is evaluation infrastructure, not the production security architecture:

- process environment is visible to sufficiently privileged host/container administrators;
- the backend image currently needs a non-root/read-only-root hardening pass;
- the bridge network does not enforce destination egress policy outside the application;
- there is one API and one database instance, with no HA, external secret manager, queue, regional worker, or tested failover;
- Docker is unavailable on the workstation used to review this document, so the manifest has not been runtime-validated here. File/config review is not proof of image pull, build, migration, health, probe, or restart behavior.

## 9. Safe API checks

The following calls contain no endpoint or credential:

```powershell
$federationBase = "http://localhost:8000/api/v1/federation"

$adapters = Invoke-RestMethod "$federationBase/adapters"
$adapters.items | Select-Object kind, label, version, available, supports_probe

$statistics = Invoke-RestMethod "$federationBase/connections/statistics"
$statistics | Select-Object total, enabled, disabled, healthy_ratio, last_probe_at

$connections = Invoke-RestMethod "$federationBase/connections?page=1&page_size=25"
$connections | Select-Object total, page, page_size
```

Do not create/update a protected profile with a command-line literal: it will remain in shell history and may be captured by process/logging tools. Use the UI or a secure test harness that reads protected values from a non-logged secret input.

After creation, inspect the network response and assert that it contains only `endpoint_display`, `endpoint_fingerprint`, `has_credential_reference`, and `encryption_key_id`. It must not contain `endpoint`, `credential_reference`, ciphertext, or a playable URL.

## 10. Manual demonstration flow

Use one sanitized camera and one authorized representative source:

1. Show backend readiness and the adapter catalog.
2. Open Stream Federation and show the real aggregate counts from the API.
3. Select a registered camera and an available adapter.
4. Enter the endpoint outside the screen-recording crop; do not enter a raw password. If required, enter only an opaque fake/local credential reference.
5. Submit once, then show the safe profile: adapter, stream role, sanitized endpoint display, enabled state, verification state, and camera context.
6. Confirm that revisiting the page does not repopulate either protected input.
7. Run one bounded probe and show its safe status, latency, observation time, and normalized metadata.
8. If the source requires authentication, open **Credential vault**, create a department-scoped device identity, and bind its generated managed profile in the connection onboarding form. The username/password must disappear after write and never be readable through the API.
9. For an eligible RTSP, HLS, MJPEG, ONVIF, or controlled recorded-file source, select **Start live** and observe `starting` transition to `live`. ONVIF start performs bounded authenticated Media1 profile negotiation before launching the resolved RTSP source. Open the live drawer and verify the same-origin playlist advances.
10. Demonstrate **Restart** and **Stop**. Stop must terminate the child process, disable playlist/segment access for that session, and remove generated media.
11. Show enable/disable behavior and explain that it changes assignment eligibility; disabling is not yet a durable distributed lease-revocation mechanism.
12. Show the safe connection and credential audit timelines. Neither may contain the endpoint, reference value, username, password, ciphertext, ONVIF XML, or RTSP URI.
13. Show a rejected cross-department credential reference, non-allowlisted endpoint, and embedded-credential endpoint using sanitized test input.
14. State explicitly: P0.3/P0.3R demonstrated secure onboarding, managed credentialed handoff, ONVIF Media1 negotiation, supervised decode/transcode, and browser live view. It does not claim durable recording, AI, watchlist matching, route reconstruction, external-vault integration, production authentication, or physical-device compatibility until the acceptance matrix is executed.

For hackathon evidence, record the build/archive identity, date/time, operating-system profile, database profile, adapter kind/version, timeout, and result. Do not record protected environment values or source topology.

## 12. Key rotation and recovery

### Disposable local database

For a disposable demonstration database, create a fresh database and fresh key together. Do not change the key for a database containing profiles and expect old ciphertext to decrypt.

### Persistent/staging database

Do not perform an ad-hoc key replacement. Use this controlled sequence:

1. Back up the encrypted database and independently escrow the current key under approved access control.
2. Inventory records by `encryption_key_id` without exporting endpoints.
3. Create the new key/key ID in the secret facility.
4. Deploy code that can decrypt old-key records and encrypt all new writes with the new key.
5. Re-encrypt in small idempotent batches, recompute the keyed endpoint fingerprint under the new key, authenticate/read back each result, and preserve rollback until counts reconcile.
6. Exercise a profile probe after rotation using an authorized sanitized source.
7. Revoke ordinary old-key access only after the rollback and backup retention window; destroy it only with formal approval.

The current single-key local Fernet setting does not by itself implement online dual-key rotation. A migration/rotation utility and managed key integration are a production requirement. Never decrypt profiles to CSV or log plaintext as part of rotation.

### Backup rules

- database backup and key backup use different systems/custodians;
- backups are encrypted and access audited;
- key retention is at least aligned to encrypted backup retention;
- restore evidence includes authorized decryptability and denial without the key;
- RPO/RTO figures come from timed restore drills, not estimates;
- restored workers retain the same narrow egress and authorization policy before probes are enabled.

## 13. Troubleshooting without disclosure

| Symptom / safe code | Check |
|---|---|
| encryption unavailable | verify the key exists and is valid without printing it; restart the backend from the configured terminal |
| endpoint decryption failed | confirm the database's `encryption_key_id` and authorized key version; do not overwrite the profile or try random keys |
| scheme not allowed | compare adapter manifest `schemes`; do not rewrite into a misleading scheme |
| embedded credentials | remove URI user information; store only an opaque credential reference for later server-side resolution |
| endpoint blocked | review the resolved address class and exact approved CIDR; do not broaden the allowlist reflexively |
| DNS resolution failed | verify approved DNS/connectivity from the worker environment without logging the endpoint |
| recorded file outside media root | stage an authorized file beneath `FEDERATION_MEDIA_ROOT`; do not weaken traversal protection |
| probe timeout | inspect safe latency/error code and source owner/network state; do not raise deadlines/retries without capacity analysis |
| adapter unavailable | inspect `unavailable_reason`; do not present generic descriptor availability as vendor compatibility |

When escalating an incident, share request ID, connection UUID, adapter kind/version, safe error code, and time. Do not paste the endpoint, credential reference, ciphertext, key, DNS response, or raw vendor error into chat/tickets.

## 14. Current deployment boundary and scale path

The P0.3 Compose profile is a production-shaped evaluation path, not a hardened production deployment. It requires key injection and mounts only the isolated media root read-only, but it does not provide managed key custody or network-enforced adapter egress. Do not bake the key into an image, Compose file, environment example, or frontend build argument.

For approximately 50 evaluation feeds, stagger synchronous probes and admit runtime sessions only within a measured worker limit; the default process-local limit of eight is a safety setting, not proof of 50-stream capacity. For approximately 80,000 cameras, move execution to regional/edge adapter workers behind a durable job queue with per-site quotas, leases, fencing, circuit breakers, dead-letter handling, crash reconciliation, and measured autoscaling. Keep central APIs stateless and send normalized observations centrally. AI/GPU sizing belongs to P0.4 and cannot be inferred from P0.3R session counts.

## 15. Stop local services

Use `Ctrl+C` in the backend and frontend terminals. Remove only the current process variables if desired:

```powershell
Remove-Item Env:FEDERATION_ENCRYPTION_KEY -ErrorAction SilentlyContinue
Remove-Item Env:FEDERATION_ENCRYPTION_KEY_ID -ErrorAction SilentlyContinue
Remove-Item Env:FEDERATION_ALLOWED_CIDRS -ErrorAction SilentlyContinue
Remove-Item Env:FEDERATION_PROBE_TIMEOUT_SECONDS -ErrorAction SilentlyContinue
Remove-Item Env:FEDERATION_MEDIA_ROOT -ErrorAction SilentlyContinue
```

This does not delete the database or media. If an ephemeral key is removed while its encrypted profiles remain, those profiles become unrecoverable unless the key was separately backed up. Deletion of a database, volume, media file, or key is intentionally outside routine stop commands.
