# P0.3R Media Runtime Threat Model

Status: security design and implementation-review baseline. It is not an authorization to connect a production camera, VMS, credential or government network.

## 1. Scope and assumptions

This model covers the P0.3R supervisor, FFmpeg-compatible standards worker, credential-resolution boundary, per-session media directory, HLS playlist/segment gateway, runtime APIs, watchdog/reconnect/circuit behavior and safe telemetry.

It excludes recording/evidence retention, analytics, ANPR, faces, watchlists, alerts, PTZ and forensic export. Those modules require separate data-classification, model-safety and evidence-chain reviews.

The runtime is an Agent-DVR-style standards path, not a Milestone device pack. ONVIF/RTSP interoperability reduces vendor lock-in but does not inherit the security fixes, device certification, firmware workarounds or proprietary driver controls of a commercial VMS.

Current P0.3 authentication remains a production gap unless P0.3R code introduces and verifies a real identity dependency. An `X-Actor-ID`-style prototype header, CORS and an opaque UUID are not authentication.

## 2. Security and reliability objectives

1. Only an authenticated and resource-authorized caller can start, inspect, stop, restart or view a runtime in production.
2. No runtime response, asset, log, audit, metric or process diagnostic exposes a source endpoint, ciphertext, credential reference/value, argv, PID, worker path or raw stderr.
3. Managed local credentials resolve only within the owning department and never enter argv; unsupported external providers fail closed.
4. FFmpeg/protocol parsing is isolated from the API and constrained by fixed policy and resource limits.
5. Playlist/segment access cannot traverse the runtime root, follow a stale generation or leak through a shared cache.
6. A dead, stalled or stale worker cannot remain reported as `live`.
7. Reconnect/backoff/circuit policy prevents a camera/site outage from becoming a retry storm.
8. Stop/restart/reconciliation cannot kill an unrelated PID or leave an orphaned secret-bearing worker.
9. H.265/transcode and malformed media cannot exhaust CPU, GPU, memory, disk or network across tenants.
10. Device acceptance records exact models/firmware and never turns two successful tests into a vendor-family or zero-failure claim.

## 3. Assets and classification

| Asset | Classification | Principal risk | Required handling |
|---|---|---|---|
| decrypted source endpoint | restricted operational topology | targeting, lateral movement, unauthorized viewing | decrypt just in time inside worker boundary; never browser-visible or logged |
| credential reference | restricted secret metadata | exposes secret-manager topology/identity | encrypted at rest; resolver-only access; never returned |
| encrypted local credential profile | critical protected data | database/key compromise grants device access | separate username/password ciphertext, department scope, write-only API, external key custody and audited rotation |
| resolved credential | critical secret | direct device/VMS access | short lease, memory only, no argv/env/log/file by default |
| FFmpeg argv/environment/stderr | restricted diagnostic | may contain topology, secrets or parser details | fixed/redacted command; bounded restricted diagnostics; absent from API |
| HLS playlist/segments | sensitive live surveillance data | unauthorized observation, privacy breach | authenticated camera-scoped access, short lifetime, private cache, no public static root |
| runtime/session intent and state | sensitive operations metadata | reveals coverage/outages; command tampering | resource authorization, generation/lease checks, audit |
| camera/site bandwidth | operational availability | probe/runtime storm degrades policing network | per-device/site budgets, backoff and circuit breaker |
| CPU/GPU/memory/disk/PIDs | shared availability | media bomb or noisy tenant | process/container quotas and scheduling admission |
| media worker image/binary | privileged executable | supply-chain compromise | pinned/signed artifact, SBOM, scan, staged rollout |
| audit/status evidence | integrity-critical | repudiation or misleading health | append-oriented safe events, trusted actor identity, protected retention |
| device model/firmware/clock results | sensitive engineering data | vulnerability/coverage inference | restricted acceptance records; sanitize external submission |

## 4. Trust boundaries

```text
[Browser/operator]
       |
       | A: untrusted client -> identity + runtime API
       v
[API/policy/state]
       |
       | B: encrypted profile -> decryption/resolver boundary
       v
[Session supervisor]
       |
       | C: trusted control -> constrained media subprocess/container
       v
[FFmpeg standards worker] ------ D: outbound camera/VMS network
       |
       | E: private generation directory
       v
[HLS asset gateway] ------------ F: authorized live media -> browser
       |
       `------------------------ G: safe logs/metrics/audit
```

Boundary C treats codec/protocol input and worker stderr as untrusted. Boundary D is SSRF/lateral-movement sensitive. Boundary F carries live surveillance data and requires stronger authorization than ordinary public web assets.

“Baseline” is a P0.3R implementation requirement to verify in code/tests. “Production” is mandatory before a real feed even if the PoC cannot fully exercise it.

| R02 | IDOR by runtime/connection UUID | cross-department surveillance | UUID never authorizes; session is resolved back to connection/camera before action | negative ABAC tests across every start/get/stop/restart/playlist/segment route |

### 5.1 Observed PoC limitations that remain open

The matrix intentionally mixes controls already present with required controls. The latest repository inspection confirmed meaningful improvements: fixed per-adapter protocol whitelists, direct-RTSP IP pinning, full-jitter retry, playlist-directive allowlisting, generation-qualified segment names, stop-time asset removal, playlist-signature advancement, descriptor-based segment open and a node session-count cap. Those controls should be cited narrowly, not generalized into production readiness.

The following limitations remain open; none may be described as closed without new code and evidence:

1. Runtime and HLS routes have no production identity or camera/department ABAC.
2. Restart reuses the session UUID, directory and playlist URL; generation is internal rather than a durable authorization/fencing lease.
3. Descriptor/no-follow handling is platform-dependent and hardlink, parent-reparse and cleanup-race behavior has not been qualified.
4. Watchdog playlist signatures advance, but a complete non-zero segment is not opened and verified before freshness is accepted.
5. Full-jitter retry exists, but per-device/site budgets, a rolling circuit, cooldown and half-open recovery do not.
6. Every eligible input is software-transcoded to `libx264`; copy/remux, H.265 policy, GPU path, codec/resource admission and per-session effective-mode fields are absent.
7. Runtime state is process-local/in-memory; duplicate start is excluded, but there is no durable lease, fencing or crash/host-reboot reconciliation.
8. The raw input endpoint is passed as the FFmpeg `-i` argument; the default resolver prevents credential injection but endpoint/query-token secrecy from privileged process inspection is not guaranteed.
9. Direct RTSP is IP-pinned, but HLS/MJPEG hostname resolution and HLS child/key/map destinations are not. The protocol whitelist limits schemes but no destination-enforcing egress control closes DNS rebinding and second-order SSRF for HTTP-family inputs.

The PoC can still demonstrate a deliberately isolated, credentialless standards path. It cannot yet be approved for a real government camera network or described as a production-secure runtime.

## 6. Credential and process-spawn security

### Default behavior

If a profile has `has_credential_reference=true` and the approved resolver cannot produce a typed short-lived credential through workload identity, `POST /api/v1/federation/connections/{connection_id}/runtime/start` must accept no insecure fallback. The resulting safe session/operation reports `unavailable` or `failed` using the frozen API semantics and a stable resolver code. No process is spawned.

The reference is not returned to the supervisor UI and is not included in an audit diff. A caller cannot supply a credential value in the runtime-start body.

### Spawn construction

- execute a fixed absolute FFmpeg path from trusted configuration;
- pass an argument array directly, never through shell/cmd/PowerShell interpolation;
- use fixed allowlists for input protocol, transport, codec, muxer, segment pattern and output root;
- create a private process group/job/cgroup and hold a native process handle;
- scrub inherited environment and working directory;
- disable stdin/interactive prompts;
- bound stderr capture by bytes/time and redact before persistence;
- never expose argv, PID, stderr or environment through the safe session schema;
- terminate/reap the complete group on stop, timeout, supervisor exit and host reconciliation.

FFmpeg does not offer a universal secret-free mechanism for every RTSP/HTTP authentication mode. This limitation must stay visible. A local credential-injecting proxy or tested vendor/native driver is preferred; an argv credential compatibility mode is not production-safe simply because `/proc` is restricted.

## 7. HLS asset security contract

The frozen asset routes are:

- `GET /api/v1/federation/runtime/sessions/{session_id}/playlist.m3u8`;
- `GET /api/v1/federation/runtime/sessions/{session_id}/segments/{asset_name}`.

`FEDERATION_RUNTIME_ROOT/<opaque-session-id>/` is private server storage. The URL never mirrors that filesystem path. `asset_name` is not a relative path; it is one filename token matching the runtime's generated segment pattern.

Required decision sequence:

1. authenticate caller (production gate; prototype header is insufficient);
2. load current session by UUID without revealing existence across scope;
3. authorize session -> connection -> camera -> department/district;
4. verify state/generation and asset lease are playable;
5. validate filename length, alphabet, extension and sequence pattern;
6. reject all separators, dot segments, percent ambiguities, NUL, drive/UNC/reparse syntax;
7. open beneath the trusted generation directory with no-follow semantics;
8. verify regular file, size/range and expected content type;
9. stream with private cache headers and bounded accounting;
10. close lease before cleanup can remove the generation.

The playlist is generated/rewritten so every segment resolves through the authorized segment route. It cannot contain absolute `file:`, `http:`, `https:`, `rtsp:` or encryption-key URIs.

## 8. Reliability abuse and circuit policy

Runtime state is public as exactly: `starting`, `live`, `degraded`, `backoff`, `stopped`, `failed`, `unavailable`. Internal phases such as stopping/reconnecting/half-open/circuit-open do not expand the API enum:

- automatic retry scheduled -> `backoff` plus `next_retry_at`-style safe timing if present;
- internal circuit open/manual intervention -> `failed` plus stable circuit error;
- half-open attempt -> a new `starting` generation;
- missing FFmpeg, unsupported driver/codec or fail-closed resolver -> `unavailable` where the implementation uses capability semantics.

Policy parameters have minimum/maximum bounds. An operator cannot set zero delay, infinite retry or unlimited segment storage through an API payload. A manual restart is authorization-checked, audited and subject to site bulkhead; it does not reset global outage history silently.

Fault injection must cover process crash, SIGKILL/forced termination, deadlock/no output, disk full, malformed playlist, HLS asset race, network blackhole/refusal, DNS change, source reboot, password rotation, host clock jump, supervisor restart and 50-session reconnect synchronization.

## 9. Codec, GPU and resource isolation

H.264 stream copy is preferred when browser/container compatible. H.265 browser compatibility is never assumed: choose a declared H.264 substream, use a measured H.265-to-H.264 transcode, or fail honestly.

Admission control evaluates codec, resolution, FPS, GOP/bitrate, copy/transcode mode, current CPU/GPU encoder/decoder capacity, transient disk and network. Source metadata is untrusted until bounded parser observation confirms it. The scheduler reserves headroom and prevents a single camera from forcing arbitrary 8K/high-FPS/software transcode.

GPU device access is privileged. Workers receive only the necessary device nodes/runtime capabilities, not host admin access. Metrics avoid camera endpoints and cross-tenant identifiers. Encoder session licensing/limits, driver reset and thermal throttling are explicit failure modes.

At 80,000 cameras, decoding is regional/edge and on demand. Centralizing 80,000 FFmpeg workers or HLS previews would multiply attack surface, bandwidth and blast radius; camera cardinality is not concurrent-runtime capacity.

## 10. Device-specific risks

Physical acceptance for each exact Hikvision and CP Plus device covers:

- ONVIF exposure/auth/profile token and media URI behavior;
- RTSP Basic/Digest behavior without embedding credentials;
- primary/substream codec/resolution/FPS/GOP;
- source reboot, network loss/recovery and reconnect rate;
- bad/rotated password and device lockout behavior;
- NTP/device clock drift and timestamp quality;
- H.265 behavior and H.264 fallback/transcode;
- concurrent client/session limit and firmware-specific failure.

Do not change firmware, reset credentials, enable services, alter clock/NTP or reboot a government device without explicit owner approval. Acceptance should use a lab-owned device or an approved maintenance window/VLAN.

## 11. Security tests required before a real feed

- OpenAPI and every runtime JSON/error/audit/log path reject or redact endpoint, ciphertext, credential reference/value, argv, PID, worker path and raw stderr canaries.
- All runtime action and asset routes reject unauthenticated and cross-department callers.
- Credentialed profile start fails before spawn with the default resolver.
- Shell metacharacters, FFmpeg option injection and unsafe protocols cannot affect the fixed command.
- DNS/private/public policy and pinned-connect tests prove the runtime worker—not only the lightweight probe—uses the authorized destination across DNS changes and IPv4/IPv6 answers.
- HLS master/media playlist redirects and child segment/key/map URIs cannot change scheme/host/port outside the approved policy; unsafe FFmpeg protocols and ambient proxies are ineffective.
- Traversal corpus covers raw/double encoding, separators, `..`, NUL, Unicode, Windows drive/UNC, symlink, junction, hardlink and cleanup TOCTOU.
- Playlist contains only authorized relative segment routes and no source/key URI.
- Cache tests prove one user's playlist/segment is never served to another.
- Stale generation assets return denial/not-found after stop/restart.
- Process crash/stall/orphan/PID reuse/start-stop race produce correct state and complete reaping.
- Backoff uses jitter and circuit prevents a 50-source retry herd.
- H.265/corrupt/high-resolution inputs cannot escape resource budgets.
- Key/password rotation revokes old leases and leaves no old worker.

## 12. Residual risk and acceptance authority

An in-process supervisor, local Fernet key, process-environment secret, prototype actor header, host FFmpeg subprocess, shared filesystem and absent destination-enforcing runtime egress control are proof-of-concept limitations. A successful local HLS preview does not authorize production use.

Standards interoperability remains dependent on device firmware/configuration and FFmpeg support. No architecture can promise zero failure. Approval requires named owners, exact device evidence, production identity/egress/key/process controls and documented residual risks.
