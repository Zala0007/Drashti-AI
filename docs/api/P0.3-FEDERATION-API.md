# P0.3 Federation API Contract

Status: current P0.3 implementation contract. The generated OpenAPI document from the running build is authoritative for exact enums, validation limits, status codes, and optional query filters.

Base path: `/api/v1/federation`

All examples and descriptions use sanitized identifiers. This document contains no operational endpoint or credential.

## 1. Contract guarantees

- Connection profile IDs and camera IDs are UUIDs; neither is an authorization mechanism.
- `endpoint` and `credential_reference` are protected write-only inputs.
- No response returns `credential_reference` or the raw endpoint.
- `endpoint_display` is a server-generated sanitized hint, not the original endpoint.
- `endpoint_fingerprint` is a keyed digest intended for internal correlation, not a connection target.
- Probe failures return stable error codes/messages; third-party exception text and raw protocol payloads are not returned.
- `normalized_metadata` contains an adapter-specific allowlist of safe fields. It must never contain a host, path, query, credential, response header, or raw vendor payload.
- An enabled profile or successful probe does not claim live view, sustained decode, recording, or AI readiness. A separate P0.3R runtime session is required for live media.
- Current actor attribution may be supplied by an untrusted local demonstration header. Production identity must come from authenticated claims.

## 2. Common error envelope

Validation and application failures use the repository-wide response shape:

```json
{
  "error": {
    "code": "STABLE_ERROR_CODE",
    "message": "Safe operator-facing message",
    "details": null,
    "request_id": "request-correlation-id"
  }
}
```

The error envelope must not echo an endpoint, credential reference, request body, response header, DNS answer, or third-party exception.

## 3. Adapter manifest

### `GET /api/v1/federation/adapters`

Returns registered adapter manifests in an `items` array. This is capability discovery, not a list of camera endpoints.

Each manifest contains:

| Field | Type | Meaning |
|---|---:|---|
| `kind` | string | stable adapter discriminator used by profile commands |
| `label` | string | operator-facing adapter name |
| `version` | string | adapter contract/implementation version |
| `schemes` | string[] | endpoint schemes accepted by the adapter validator |
| `capabilities` | string[] | declared adapter capabilities; not an observed camera result |
| `supports_discovery` | boolean | whether bounded discovery is implemented |
| `supports_probe` | boolean | whether a lightweight probe is implemented |
| `supports_stream_handoff` | boolean | whether the adapter declares a future server-side handoff contract |
| `available` | boolean | whether this build can execute the declared adapter behavior |
| `unavailable_reason` | string/null | safe explanation when the adapter is not executable |

The implemented adapter kinds are `rtsp`, `hls`, `mjpeg`, `onvif`, `vms_http`, and `recorded_file`. Clients must use the returned manifests rather than hard-code availability. The `vms_http` adapter does not imply support for every proprietary vendor SDK. All current manifests report `supports_discovery=false`; network-wide discovery is not implemented by P0.3.

### Government evaluation catalogue

`GET /api/v1/federation/catalogues/government-feeds` performs bounded, HTTPS-only discovery from the configured provider catalogue. It returns safe camera identity, provider location text, live/codec/dimension summaries, and onboarding state. It never returns RTSP, HLS, WHEP, credential, cookie, token, host, or path values.

`POST /api/v1/federation/catalogues/government-feeds/sync` validates that every media endpoint belongs to the configured provider, then idempotently upserts cameras plus encrypted RTSP/TCP primary and HTTPS HLS fallback profiles. The transaction fails as a unit on invalid or conflicting catalogue data. Provider location text does not include coordinates, so imported centroid coordinates carry `coordinates_provisional=true` until GIS verification.

## 4. Safe connection representation

Every connection read/action returns the same safe connection shape:

| Field | Type | Meaning / secrecy rule |
|---|---:|---|
| `id` | UUID | immutable connection-profile identity |
| `name` | string | non-secret operator label |
| `adapter_kind` | string | adapter manifest `kind` |
| `stream_role` | string | `primary`, `substream`, `playback`, or `metadata` |
| `endpoint_display` | string | sanitized server-generated display; DNS labels/IP portions and path identity are masked, and recorded files expose only a bounded suffix; never use it as a target |
| `endpoint_fingerprint` | string | keyed endpoint correlation digest |
| `enabled` | boolean | assignment eligibility; does not start streaming |
| `priority` | integer | ordering among a camera's connection candidates |
| `verification_status` | string | `unverified`, `reachable`, `unreachable`, `authentication_required`, `blocked`, `misconfigured`, `adapter_unavailable`, or `disabled` |
| `last_probe_at` | datetime/null | UTC time of latest completed probe |
| `last_probe_latency_ms` | number/null | bounded probe duration |
| `last_error_code` | string/null | stable normalized failure code |
| `last_error_message` | string/null | sanitized operator message |
| `last_success_at` | datetime/null | UTC time of most recent successful lightweight probe |
| `failure_count` | integer | consecutive unsuccessful probes; reset after a `reachable` result |
| `normalized_metadata` | object | allowlisted observations limited to `protocol`, `status_code`, `content_type`, `media_type`, and `size_bytes` when applicable |
| `encryption_key_id` | string | non-secret key version identifier; never key material |
| `has_credential_reference` | boolean | whether protected opaque credential metadata is stored |
| `created_by` | string | actor attribution; untrusted in local mode until authentication exists |
| `created_at` | datetime | UTC creation time |
| `updated_at` | datetime | UTC last mutation time |
| `camera` | object | safe camera summary described below |

`camera` contains:

| Field | Type |
|---|---:|
| `id` | UUID |
| `camera_code` | string |
| `camera_name` | string |
| `department_id` | UUID |
| `department_code` | string |
| `department_name` | string |
| `district` | string |
| `city` | string/null |
| `latitude` | number |
| `longitude` | number |

The camera summary contains registry metadata only. No registry `stream_reference`, registry `credential_reference`, raw profile endpoint, storage topology, or secret value is added to it.

## 5. List and statistics

### `GET /api/v1/federation/connections`

Returns a standard page containing `items`, `total`, `page`, `page_size`, and `pages`.

| Query | Type | Meaning |
|---|---:|---|
| `camera_id` | UUID string | exact registered camera identity |
| `adapter_kind` | enum | one implemented adapter kind |
| `verification_status` | enum | one verification state listed above |
| `enabled` | boolean | profile assignment eligibility |
| `search` | string | 1-200 character search across safe profile and camera fields |
| `page` | integer | 1-based page, default `1` |
| `page_size` | integer | 1-500 records, default `50` |

Default list behavior must not expose protected values through sorting, filtering, validation messages, or URL query state.

### `GET /api/v1/federation/connections/statistics`

Returns aggregate operational metadata:

```json
{
  "total": 0,
  "enabled": 0,
  "disabled": 0,
  "by_status": {},
  "by_adapter_kind": {},
  "healthy_ratio": 0.0,
  "last_probe_at": null
}
```

The zeros above describe an empty sanitized deployment; they are not a performance result. `healthy_ratio` is the percentage of all matching profiles whose verification state is `reachable`, rounded to two decimal places. It is not frame availability or AI accuracy. This endpoint accepts the same five operational filters as the list endpoint, excluding pagination.

## 6. Create a connection profile

### `POST /api/v1/federation/connections`

Accepted fields:

| Field | Required | Meaning |
|---|---:|---|
| `camera_id` | yes | existing, eligible P0.1 camera UUID |
| `name` | yes | non-secret operator label, 2-160 characters |
| `adapter_kind` | yes | available manifest `kind` |
| `endpoint` | yes | protected write-only endpoint, 4-4096 characters; scheme must match adapter |
| `stream_role` | no | defaults to `primary`; accepts `primary`, `substream`, `playback`, or `metadata` |
| `credential_reference` | no | protected opaque `credential-profile:`, `vault-ref:`, or `kms-ref:` identifier up to 500 characters; never a credential value or URL |
| `priority` | no | `0`-`1000`, default `100`; lower values sort first among enabled profiles |
| `enabled` | no | defaults to `true`; profile eligibility only, not stream startup |

Unknown fields and embedded URI credentials are rejected. A retired camera cannot receive a new connection. Name uniqueness is enforced case-insensitively for the same camera and stream role. Creation requires configured endpoint encryption. The endpoint and optional credential reference are encrypted independently before persistence; the returned object is the safe connection representation.

Illustrative values must use documentation-only/reserved addresses and fake opaque references. Never paste a government endpoint, username, password, API token, or production vault path into source control, an issue, a test fixture, a demo recording, or this documentation.

## 7. Read and update

### `GET /api/v1/federation/connections/{connection_id}`

Returns the safe connection representation. It never returns the protected endpoint or credential reference, including to the actor who created the profile.

### `PATCH /api/v1/federation/connections/{connection_id}`

Accepted optional fields:

| Field | Semantics |
|---|---|
| `name` | replace non-secret label |
| `endpoint` | replace protected endpoint after adapter/network validation; omission retains current value |
| `credential_reference` | replace protected opaque reference; explicit `null` clears it; omission retains it |
| `adapter_kind` | select another registered adapter; endpoint compatibility is revalidated |
| `stream_role` | replace role |
| `priority` | replace bounded ordering value |
| `enabled` | change eligibility flag |

The response remains redacted. A protected update must refresh the relevant ciphertext/key ID and safe fingerprint/display. Failed validation must not partially replace the prior working ciphertext.

Concurrent update semantics and optimistic versioning, if any, are defined by the generated contract. Production deployment should reject lost updates rather than silently accepting stale operator state.

## 8. Probe and lifecycle actions

### `POST /api/v1/federation/connections/{connection_id}/probe`

Executes one synchronous, deadline-bound lightweight probe and returns the updated safe connection. The endpoint is decrypted only inside the server-side operation. The response records the new `verification_status`, timing, normalized metadata or safe error fields, and failure/success timestamps.

Probe semantics by adapter:

- RTSP: pinned, bounded `OPTIONS` control-plane handshake and safe response status metadata;
- HLS: pinned HTTP status/content-type validation plus a maximum 4 KiB playlist-prefix check for `#EXTM3U`; no media segment or key URI is followed;
- MJPEG: pinned, bounded HTTP response-status and multipart/JPEG content-type validation; the frame body is not retained;
- ONVIF: pinned, bounded `GetSystemDateAndTime` SOAP request with safe HTTP result metadata, not response XML parsing or arbitrary subnet discovery;
- generic VMS (`vms_http`): pinned HTTP reachability behavior, not a claim of proprietary SDK compatibility;
- recorded file: validate an application-controlled artifact beneath `FEDERATION_MEDIA_ROOT`.

The probe itself does not retain the connection or decode frames continuously. P0.3R runtime endpoints separately supervise eligible media sources and expose a bounded live HLS view; they do not run AI or create durable recordings.

### `POST /api/v1/federation/connections/{connection_id}/enable`

Marks the profile eligible for later assignment and returns the safe connection. Enablement does not prove reachability and does not start continuous streaming.

### `POST /api/v1/federation/connections/{connection_id}/disable`

Removes the profile from assignment eligibility and returns the safe connection. Stop any active process-local P0.3R session explicitly. Production distributed workers require durable lease revocation and fencing; the profile flag alone makes no cross-process termination claim.

## 9. Audit

### `GET /api/v1/federation/connections/{connection_id}/audit`

Returns the standard paginated safe audit representation in reverse chronological order. Implemented actions are `connection.created`, `connection.updated`, `connection.probed`, `connection.enabled`, and `connection.disabled`.

`page` defaults to `1`. `page_size` defaults to `50` and is bounded to `1`-`200`. The response includes `items`, `total`, `page`, `page_size`, and `pages`.

Audit may contain safe connection/camera UUIDs, action, actor label, request correlation ID, timestamps, and redacted state changes. It must never contain:

- the raw endpoint or a reversible derivative;
- credential reference or credential material;
- ciphertext, nonce, encryption key, or fingerprint key;
- raw DNS answers, protocol headers/payloads, filesystem path, or vendor exception text.

Local `created_by` or actor headers are not cryptographically verified identity. Production audit attribution must originate from authenticated OIDC/workload claims.

## 10. Validation and security behavior

### Endpoint admission

- scheme must be declared by the selected adapter;
- embedded username/password is rejected;
- network endpoints are resolved and address classes validated;
- private/loopback targets require membership in `FEDERATION_ALLOWED_CIDRS`;
- metadata, link-local, multicast, unspecified, and reserved targets are rejected;
- recorded-file sources must resolve beneath `FEDERATION_MEDIA_ROOT`;
- credential references accept only supported opaque reference prefixes/characters.

The network adapters connect to a policy-approved resolved IP; HTTP-family probes preserve the validated hostname only for the `Host` header and TLS SNI, do not inherit proxy settings, and do not follow redirects. All DNS results are validated before one is selected. Production workers must still apply firewall/container egress policy as defense in depth. Public unicast is permitted by the evaluation baseline; private/loopback targets require explicit CIDRs.

### Encryption configuration

- `FEDERATION_ENCRYPTION_KEY` is a URL-safe Fernet key representing 32 random bytes;
- `FEDERATION_ENCRYPTION_KEY_ID` labels the key version and is returned as non-secret metadata;
- missing encryption configuration makes protected operations unavailable rather than storing plaintext;
- decryption failure returns a safe service error and must not overwrite ciphertext.

Fernet is the local implementation baseline. Production deployment should use a managed KMS/HSM/secret service and a versioned envelope-encryption/rotation process rather than distributing a long-lived shared application key manually.

## 11. Status-code expectations

| Status | Meaning |
|---:|---|
| `200` | successful read, patch, probe, enable, or disable |
| `201` | connection profile created |
| `400` | invalid adapter/endpoint/policy/action configuration |
| `404` | camera or connection profile does not exist |
| `409` | uniqueness, eligibility, or state conflict |
| `422` | structured request-schema validation failure |
| `502` | a policy-approved upstream ONVIF device returned an invalid/authentication/fault response during media negotiation |
| `503` | encryption configuration/decryption or required service dependency unavailable |
| `405` | unsupported action such as physical profile deletion |

Exact statuses are frozen by OpenAPI and automated tests. A transport-level success is not equivalent to a successful probe; inspect `verification_status` and the safe error fields.

## 12. Encrypted managed credential profiles

Managed device identities use `/api/v1/federation/credentials`. They are a deployable local resolver for evaluation and isolated installations; production may replace resolution with an external Vault/KMS adapter while retaining the same opaque connection reference.

| Method and path | Result |
|---|---|
| `GET /credentials` | paginated safe metadata; filters: `department_id`, `enabled`, `search` |
| `POST /credentials` | `201`; create a department-scoped `username_password` identity from write-only `username` and `password` inputs |
| `GET /credentials/{profile_id}` | safe profile metadata only |
| `PATCH /credentials/{profile_id}` | rename, rotate write-only username/password fields, or enable/disable |
| `GET /credentials/{profile_id}/audit` | safe create/rotation/enablement history |

The response contains `id`, `reference`, owning department, non-secret name/type/status, booleans indicating protected values exist, encryption key ID, actor/timestamps, and last use. It never contains username, password, ciphertext, hashes, a reversible display value, or a secret-manager path.

The connection reference is `credential-profile:<uuid>`. Creation/update of a connection rejects a local reference that does not exist or belongs to another department. Runtime resolution also checks existence, enabled state, and exact camera-department ownership before decrypting. Password rotation replaces ciphertext and records only `secret_rotated=true` in audit. Successful assignment records `credential.used` with safe connection/session UUIDs and updates `last_used_at`.

Disabling or rotating a profile affects new runtime resolutions. The current process-local baseline does not revoke an already running FFmpeg generation; stop/restart it explicitly. Production leases must carry a credential version and propagate revocation to regional workers.

The local store uses the configured federation Fernet key. It does not replace managed production key custody, workload identity, envelope-key rotation, dual control, or a government-approved secret manager. External `vault-ref:` and `kms-ref:` references remain accepted as opaque integration metadata but fail closed at runtime until a resolver plugin is deployed.

## 13. P0.3R supervised media runtime

P0.3R adds a process-local supervised media runtime beneath the same base path. Session responses expose only safe camera/profile summaries, state, timestamps, counters, sanitized errors, and an application-relative playlist URL. They never expose the source endpoint, credential reference, ciphertext, FFmpeg arguments, PID, stderr, or worker filesystem path.

### Runtime routes

| Method and path | Result |
|---|---|
| `GET /runtime/capabilities` | binary availability/source, eligible and ineligible adapters, HLS policy, capacity, supervision settings, credential-resolver mode, safe handoff limitations, and `process_local_poc` boundary |
| `GET /runtime/sessions` | current process-local safe session snapshots |
| `POST /connections/{connection_id}/runtime/start` | `202`; admits one active session for an enabled eligible profile or returns a stable conflict/unavailable error |
| `GET /runtime/sessions/{session_id}` | one safe session snapshot |
| `POST /runtime/sessions/{session_id}/stop` | terminates the worker, cleans generated media, and returns terminal state |
| `POST /runtime/sessions/{session_id}/restart` | `202`; resets the supervised session through a new internal generation |
| `GET /runtime/sessions/{session_id}/playlist.m3u8` | allowlisted, rewritten private/no-store HLS playlist for an active session |
| `GET /runtime/sessions/{session_id}/segments/{asset_name}` | descriptor-opened, bounded generated MPEG-TS asset for an active session |

Public session states are `starting`, `live`, `degraded`, `backoff`, `stopped`, `failed`, and `unavailable`. `live` means the child process and generated playlist have made recent progress; it does not establish image quality, clock correctness, ANPR fitness, or analytics health.

Eligible adapter kinds are currently direct `rtsp`, `hls`, `mjpeg`, ONVIF Media1, and controlled `recorded_file`. ONVIF requires an enabled local managed credential profile, negotiates the primary or lowest-bandwidth substream through `GetCapabilities`, `GetProfiles`, and `GetStreamUri`, and independently revalidates every derived HTTP/RTSP endpoint. `vms_http` remains unavailable until a vendor-specific driver resolves an authorized media URI. External `vault-ref:` and `kms-ref:` values remain fail-closed until their workload-identity resolvers are configured.

The source endpoint is supplied to FFmpeg using a protected one-entry FFconcat manifest on stdin, while the process argument contains `pipe:0`. For a managed credential profile the authenticated URI exists only inside the worker/runtime memory and protected stdin path; it is absent from argv, environment, responses and audit. FFmpeg receives a fixed adapter-specific protocol whitelist, uses no shell, and runs with a scrubbed environment. Direct and ONVIF-resolved RTSP are pinned to an endpoint-policy-approved IP. HLS/MJPEG hostname and HLS child URI destination enforcement still require an egress proxy/firewall boundary before production use.

Playlist and segment routes are application endpoints, not a public static-directory mount. They validate session state, allowlist playlist tags, constrain generated asset names, and set private/no-store and `nosniff` response headers. Production authentication/ABAC must authorize every session and asset request.

### Current runtime boundary

Session state, capacity, retry state, and generations are in memory in one API process. An API restart loses that state, and multiple replicas do not coordinate. Therefore this baseline is suitable for controlled evaluation, not HA or statewide deployment. Production extraction requires regional worker identity, a durable queue, leases/fencing, crash reconciliation, per-site admission/circuits, network-enforced egress, private object/evidence storage, and audited revocation.

## 14. P0.4 analytics handoff boundary

P0.4 may consume a supervised internal frame/packet handle or obtain its own authorized worker lease. It must not scrape browser HLS, retrieve a plaintext endpoint through a browser API, or write resolved credentials to analytics persistence or telemetry. Analytics health, model/version provenance, detections, evidence, watchlist decisions, alerts, and vehicle routes require their own contracts and acceptance tests.
