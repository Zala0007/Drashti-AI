# P04 stream processing API

Base path: `/api/v1/streams`

No response contains a source URI, username, password, or credential reference.
The current `X-Actor-ID` header is audit attribution only and must not be treated
as authentication.

## Capabilities and inventory

### `GET /capabilities`

Returns decoder availability/source, configured backend, active hardware/GPU
flags, batching/latest-frame support, source types, and node session capacity.

### `GET /metrics`

Returns current per-camera-state counts, average decode/dispatch FPS and latency,
frame/drop/reconnect totals, AI queue/consumer state, and aggregate Python +
FFmpeg CPU/RSS/process telemetry. GPU/network fields are nullable until an
exporter supplies them.

### `GET /`

Returns every process-local session snapshot, newest first. Historical stopped
sessions remain observable until process restart; aggregate operational metrics
use only the newest session per camera.

## Lifecycle

### `POST /{camera_id}/start`

Selects the enabled lowest-priority P03 connection unless `connection_id` is
specified. Resolves credentials/ONVIF entirely in the backend and returns `202`.

Optional JSON body:

```json
{
  "connection_id": "00000000-0000-0000-0000-000000000000",
  "target_fps": 10,
  "decode_fps": 12,
  "transport": "tcp",
  "max_frame_age_ms": 750
}
```

Only one active processing session is admitted per camera on a node.

### `POST /{camera_id}/stop`

Stops and releases the decoder, frame buffer, process, and credential lease.

### `POST /{camera_id}/restart`

Stops the current session, securely resolves a fresh source/credential lease,
and creates a new stream session. It accepts the same optional body as `start`.

### `GET /{camera_id}/health`

Returns the latest session state, safe error, timestamps, configuration and
per-stream metrics.

## Operator preview

### `GET /{camera_id}/preview.jpg`

Returns the latest cached-buffer frame immediately, or `204` while the decoder has not
produced a frame. The Live Operations wall uses this endpoint with visible-only,
staggered polling so preview delivery does not reserve browser or server connections
needed by other portal operations.

### `GET /{camera_id}/preview.mjpg`

Returns a private/no-store multipart MJPEG preview for compatibility and focused
single-camera consumers. The 30-camera portal wall does not use it. JPEGs
are derived from the same P04 latest-frame buffer; the endpoint does not launch a
second source decoder. The response ends when the session stops.

Production must enforce view permission before this endpoint is exposed. The
current build has no authentication module and is limited to a controlled demo
network.

## AI consumer interface

P05 is an in-process/internal worker interface rather than a public frame API:

```python
batch = stream_engine.next_batch(timeout=0.2)
for packet in batch.packets:
    # packet.camera_id, packet.capture_timestamp, packet.payload, ...
```

Raw frames are intentionally not serialized through REST. A distributed P05
deployment should use a node-local transport or shared GPU memory, while sending
only normalized detections/events to the central message bus.
