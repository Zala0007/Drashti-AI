# P0.1 Camera Registry API

Base path: `/api/v1`

Interactive development documentation is exposed by FastAPI at `/docs`; the machine-readable OpenAPI document is at `/openapi.json`. This file describes the intended P0.1 contract and its security boundary. When implementation and prose differ during development, resolve the difference and update both before demonstration.

## Security status

P0.1 does not implement authentication or resource-scoped authorization. Run it only on localhost or a protected internal evaluation network. Do not publish the API directly to the internet and do not connect it to real government camera infrastructure.

No endpoint accepts camera usernames, passwords, tokens, or credential-bearing stream URLs. `stream_reference` and `credential_reference`, when present, are opaque non-secret identifiers only; they are not resolved by P0.1.

## Conventions

- Request and response media type: `application/json`, except CSV import.
- Identifiers: UUID strings.
- Time: ISO 8601 UTC timestamps.
- Coordinates: WGS 84 decimal degrees; GeoJSON coordinate order is `[longitude, latitude]`.
- List responses are paginated objects with `items`, `total`, `page`, `page_size`, and `pages` unless the endpoint explicitly returns GeoJSON or statistics.
- Request validation and domain failures use the structured `error.code`, `error.message`, `error.details`, and `error.request_id` envelope. Callers must branch on status/code, not parse English prose.
- Mutation requests may send `X-Actor-ID` for prototype audit labeling. It is untrusted caller input, **not authentication or verified attribution**.

### Enumerations

| Field | Values |
|---|---|
| `status` | `planned`, `active`, `maintenance`, `inactive`, `retired` |
| `health` | `unknown`, `online`, `offline`, `degraded` |
| `camera_type` | `fixed`, `ptz`, `dome`, `bullet`, `anpr`, `thermal`, `panoramic`, `analog`, `other` |
| `connectivity_type` | `fiber`, `mpls`, `broadband`, `cellular_4g`, `cellular_5g`, `lan`, `wireless`, `satellite`, `unknown` |
| `stream_protocol` | `rtsp`, `onvif`, `hls`, `http`, `vendor_sdk`, `none` |
| `ownership` | `government`, `private`, `public_private`, `unknown` |

## Department endpoints

### `GET /departments`

Lists departments.

Query parameters:

| Name | Type | Meaning |
|---|---:|---|
| `page` | integer | 1-based page number |
| `page_size` | integer | bounded number of records per page |
| `search` | string | searches department code/name |
| `include_inactive` | boolean | includes inactive departments when true |

Example:

```http
GET /api/v1/departments?page=1&page_size=50
```

### `POST /departments`

Creates a department.

```json
{
  "code": "HOME",
  "name": "Home Department",
  "description": "Representative hackathon department"
}
```

Department codes are stable, case-normalized identifiers and must be unique.

### `GET /departments/{department_uuid}`

Returns one department.

### `PATCH /departments/{department_uuid}`

Updates `name`, `description`, and/or `is_active`. Department codes are not mutable through this endpoint.

## Camera endpoints

### `GET /cameras`

Returns a filtered, paginated camera inventory.

| Query | Type | Behavior |
|---|---:|---|
| `search` | string | matches camera code/name, location, district/city, vendor/VMS, and department code/name |
| `department_id` | UUID | limits results to a department |
| `district` | string | case-insensitive exact district match |
| `city` | string | case-insensitive exact city match |
| `vendor` | string | case-insensitive exact camera-vendor match |
| `vms` | string | case-insensitive exact VMS name match |
| `camera_type` | enum | camera-type filter |
| `status` | enum | lifecycle filter |
| `health` | enum | operational-health filter |
| `connectivity_type` | enum | connectivity filter |
| `stream_protocol` | enum | advertised protocol filter |
| `ai_capability` | string | cameras advertising the named capability |
| `ai_enabled` | boolean | whether any AI capability is enabled |
| `tag` | string | normalized exact tag filter |
| `include_retired` | boolean | includes retired records when true; false by default |
| `bbox` | string | `west,south,east,north` WGS 84 bounding box; antimeridian crossing is supported |
| `near_lat`, `near_lon`, `radius_m` | number | nearby filter; all three are required together |
| `page` | integer | 1-based page number |
| `page_size` | integer | bounded page size |

```http
GET /api/v1/cameras?district=Ahmedabad&health=online&ai_capability=anpr&page=1&page_size=25
```

### `POST /cameras`

Creates one camera. Required fields are `camera_code`, `camera_name`, `department_id`, `district`, `latitude`, and `longitude`; defaults may supply other fields.

```json
{
  "camera_code": "HOME-AHD-001",
  "camera_name": "Ashram Road Junction — East",
  "department_id": "11111111-1111-4111-8111-111111111111",
  "district": "Ahmedabad",
  "city": "Ahmedabad",
  "location_description": "Representative location; no production endpoint",
  "latitude": 23.0304,
  "longitude": 72.5696,
  "camera_type": "anpr",
  "vendor": "Representative Vendor",
  "model": "Demo Model",
  "vms": "Department VMS",
  "connectivity_type": "fiber",
  "stream_protocol": "rtsp",
  "rtsp_capable": true,
  "onvif_capable": true,
  "status": "active",
  "ai_enabled": true,
  "ai_capabilities": ["vehicle_detection", "anpr"],
  "storage_details": {
    "type": "department_nvr",
    "retention_days": 15
  },
  "ownership": "government",
  "owner_name": "Home Department",
  "tags": ["junction", "demo"],
  "stream_reference": "connection-profile:home-ahd-001",
  "credential_reference": "vault-ref:home/demo-camera-001"
}
```

The two reference values above are illustrative identifiers, not real endpoints or secrets. A value containing embedded credentials must be rejected operationally even if it is syntactically a string.

### `GET /cameras/{camera_uuid}`

Returns one camera by immutable UUID. A UUID is not an authorization mechanism; future RBAC must independently authorize the resource.

### `PATCH /cameras/{camera_uuid}`

Applies a partial metadata update. Identity fields and audit history must not be silently replaced. Example:

```json
{
  "status": "maintenance",
  "tags": ["junction", "lens-service-due"]
}
```

### `POST /cameras/{camera_uuid}/retire`

Transitions a camera to `retired` without deleting its UUID or audit history. Downstream services should exclude retired cameras from new processing assignments by default.

```json
{
  "reason": "Asset decommissioned after approved replacement"
}
```

### `POST /cameras/{camera_uuid}/heartbeat`

Records an operational heartbeat.

```json
{
  "health": "online"
}
```

A heartbeat reports service reachability/health supplied to the registry. It is not proof of useful frames, valid credentials, adequate FPS, or successful AI inference.

### `GET /cameras/{camera_uuid}/audit`

Returns camera audit entries in chronological or reverse-chronological order as specified by the implementation, with pagination where supported. Clients must not depend on database row order. Audit content is safe metadata only.

## GIS and summary endpoints

### `GET /cameras/filter-options`

Returns safe, sorted, distinct filter values observed in camera inventory. Retired
cameras are excluded by default. Pass `include_retired=true` to derive the options
from active and retired camera records together.

The response contains exactly these arrays:

| Field | Type | Source |
|---|---|---|
| `districts` | `string[]` | observed non-empty camera districts |
| `cities` | `string[]` | observed non-empty camera cities |
| `vendors` | `string[]` | observed non-empty camera vendors |
| `vms` | `string[]` | observed non-empty VMS names |
| `ai_capabilities` | `string[]` | observed camera AI-capability entries |
| `camera_types` | `string[]` | observed camera types |
| `connectivity_types` | `string[]` | observed connectivity types |
| `stream_protocols` | `string[]` | observed stream protocols |

The endpoint does not expose stream references, credential references, storage
metadata, installation metadata, or camera records. An inventory with no matching
records returns the same object with empty arrays.

### `GET /cameras/geojson`

Returns a GeoJSON `FeatureCollection`. It accepts the same operational filters as `GET /cameras` (without pagination in P0.1).

`limit` bounds returned features from 1 to 10,000 and defaults to 5,000. `number_matched` can therefore be greater than `number_returned`.

```json
{
  "type": "FeatureCollection",
  "features": [
    {
      "type": "Feature",
      "id": "22222222-2222-4222-8222-222222222222",
      "geometry": {
        "type": "Point",
        "coordinates": [72.5696, 23.0304]
      },
      "properties": {
        "camera_uuid": "22222222-2222-4222-8222-222222222222",
        "camera_code": "HOME-AHD-001",
        "camera_name": "Ashram Road Junction — East",
        "department_name": "Home Department",
        "district": "Ahmedabad",
        "status": "active",
        "health": "online",
        "ai_enabled": true
      }
    }
  ],
  "number_matched": 1,
  "number_returned": 1
}
```

At statewide density this endpoint must evolve to accept map bounds/zoom or return server-side clusters/vector tiles. P0.1's full filtered feature collection is a prototype boundary, not an 80,000-marker browser strategy.

### `GET /cameras/statistics`

Returns aggregate counts and accepts the same inventory filters:

## Bulk CSV import

### `POST /cameras/import`

Content type: `multipart/form-data`; file field: `file`.

The synchronous P0.1 importer is deliberately bounded to **10 MiB**, **10,000 data
rows**, and **65,536 characters per field**. Parser/limit violations return a
structured `400` response and roll back the entire import; ordinary row validation
errors remain row-level results. Larger statewide loads belong in a later
asynchronous, persisted import-job workflow.

PowerShell example:

```powershell
curl.exe -X POST `
  -H "Idempotency-Key: local-seed-v1" `
  -F "file=@database/seeds/cameras.csv;type=text/csv" `
  "http://localhost:8000/api/v1/cameras/import?on_duplicate=error"
```

The canonical sample is [`database/seeds/cameras.csv`](../../database/seeds/cameras.csv). It contains sanitized representative data only. Import behavior must expose row numbers and validation reasons for rejected rows; callers should inspect the structured result rather than assuming every row succeeded.

Example result shape:

```json
{
  "total_rows": 10,
  "created": 9,
  "updated": 0,
  "skipped": 0,
  "failed": 1,
  "import_id": "33333333-3333-4333-8333-333333333333",
  "idempotency_key": "local-seed-v1",
  "replayed": false,
  "results": [
    {
      "row_number": 7,
      "camera_code": "DEMO-INVALID-007",
      "status": "failed",
      "camera_id": null,
      "error": {
        "code": "ROW_VALIDATION_ERROR",
        "message": "CSV row validation failed",
        "details": [
          {
            "field": "latitude",
            "message": "Input should be less than or equal to 90",
            "type": "less_than_equal"
          }
        ]
      }
    }
  ]
}
```

The counts above illustrate the response contract; they are not an observed import result.

## Expected status handling

| Status | Meaning |
|---:|---|
| `200` | successful read/update/action |
| `201` | resource created, where implemented |
| `400` | malformed import or invalid operation |
| `404` | department/camera not found |
| `409` | unique camera/department code conflict |
| `422` | structured request validation failure |
| `500` | unexpected server failure; no secret-bearing detail should be returned |

Exact creation/import statuses are represented in the generated OpenAPI contract and must be frozen before external client integration.

## PowerShell smoke sequence

After starting the backend:

```powershell
$base = "http://localhost:8000/api/v1"

$department = Invoke-RestMethod -Method Post -Uri "$base/departments" `
  -ContentType "application/json" `
  -Body (@{
    code = "HOME"
    name = "Home Department"
    description = "Local representative data"
  } | ConvertTo-Json)

$camera = Invoke-RestMethod -Method Post -Uri "$base/cameras" `
  -ContentType "application/json" `
  -Body (@{
    camera_code = "HOME-AHD-001"
    camera_name = "Representative Ahmedabad Camera"
    department_id = $department.id
    district = "Ahmedabad"
    latitude = 23.0304
    longitude = 72.5696
  } | ConvertTo-Json)

Invoke-RestMethod -Uri "$base/cameras/$($camera.id)"
Invoke-RestMethod -Uri "$base/cameras/geojson"
Invoke-RestMethod -Uri "$base/cameras/statistics"
```

Use a fresh database or unique codes when repeating the sequence. This is a manual verification recipe, not a claim that the commands have run in a particular environment.
